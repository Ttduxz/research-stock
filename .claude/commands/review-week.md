รันคิวติดตามประจำสัปดาห์ให้จบในรอบเดียว: $ARGUMENTS

**เป้าหมายของคำสั่งนี้คือ user สั่งครั้งเดียวแล้วไม่ต้องมาสั่งซ้ำ** — ทำครบทุกตัวในคิว รวมถึงตัวที่ต้องวิเคราะห์ใหม่ แล้วสรุปทีเดียวตอนจบ

## กติกาคุม context (สำคัญที่สุด — ทำให้จบใน session เดียวได้)

orchestrator ต้องกิน context ให้น้อยที่สุดต่อ ticker (~1k token) โดย:

- **ห้ามอ่านไฟล์ JSON ของ pipeline เอง** (`prev-context.json` ~43KB, `research.json`, `review.json`) — ส่งแค่ *path* ให้ agent แล้วให้มันอ่านเอง
- **ห้าม cat/echo เนื้อไฟล์** ตรวจว่าไฟล์ถูกสร้างด้วย `ls` หรือดูบรรทัดผลลัพธ์ของสคริปต์พอ
- ระหว่างทำ **โพสต์แค่บรรทัดเดียวต่อ ticker** (เช่น `NVDA ✓ ยืนยันเดิม`) ไม่ต้องเล่ารายละเอียดระหว่างทาง — รายละเอียดไปอยู่ในสรุปตอนจบซึ่งอ่านจาก DB
- ถ้า agent ตอบยาว ให้สรุปเก็บแค่ stance + plan_status ไม่ต้อง quote

ด้วยกติกานี้ 29 ticker กิน context ราว 30k เท่านั้น — ไม่ต้องแบ่ง session

## ขั้นตอน

**1. ดูคิว** (ไม่ใช้ agent)
```
node scripts/price-delta.mjs --due --json
```
ได้ list ของหุ้นที่ค้างเกิน 7 วัน (ปรับด้วย `--due=N`) พร้อม `escalate_reasons`, `suggested_run_type`, `price_suspicious`

บอก user เป็นตารางสั้นๆ ว่าจะทำกี่ตัว ตัวไหนมีธงแล้วเริ่มได้เลย **ไม่ต้องรอ user ยืนยัน** — ถ้าคิวว่าง บอกว่าไม่มีตัวไหนค้างแล้วจบ

ถ้า `--max=N` ถูกส่งมา ให้ทำแค่ N ตัวแรกของคิว

**2. วนทำทีละ ticker** — ต่อหนึ่งตัวทำตามนี้ (เหมือน `/review-stock` แต่ไม่ต้องรายงานระหว่างทาง):

```
DIR=pipeline/output/<TICKER>-review-<วันนี้>
node scripts/prev-context.mjs <TICKER> > $DIR/prev-context.json
node scripts/price-delta.mjs <TICKER> --json > $DIR/price-delta.json
```
- spawn `stock-researcher` (โหมดติดตาม) → `$DIR/research.json` — ส่ง path ของ prev-context ให้มันอ่านเอง
- ถ้ามี `hints` ที่ผ่านเกณฑ์และไม่ซ้ำ (เช็คด้วย `node scripts/list-hints.mjs`) → spawn `hint-analyst` → `ingest-hint.mjs` (ปกติไม่มี)
- spawn `stock-reviewer` → `$DIR/review.json` — ส่ง path ทั้ง 3 ไฟล์
- `node scripts/ingest-review.mjs $DIR/review.json $DIR/research.json`
- โพสต์บรรทัดเดียว: `<TICKER> — <stance> · <plan_status>`

**ถ้า ingest ปฏิเสธ** (claim ไม่ตรงเป๊ะ / ไม่มีหลักฐาน / ไม่มี action_md): ส่งกลับให้ reviewer แก้ **หนึ่งครั้ง** ถ้ายังไม่ผ่านให้ข้ามตัวนั้นแล้วบันทึกไว้รายงานตอนจบ — **ห้ามใส่ `--force` เพื่อให้ผ่าน** และห้ามหยุดทั้งคิวเพราะตัวเดียวพัง

**3. ตัวที่ต้องวิเคราะห์ใหม่** — หลังวนครบทุกตัวแล้วค่อยทำ (ไม่ทำแทรกกลางคิว เพราะกิน context มาก)

รัน `/research-stock <TICKER>` เต็มรูปแบบเฉพาะตัวที่: `stance` = `escalate` **หรือ** มี check ไหน `broken` **หรือ** ครบ 8 สัปดาห์ตั้งแต่ full run **หรือ** มีงบใหม่ออก
เวลา ingest ให้ใส่ `"review_id"` + `"run_type": "update"` ใน `run` ของ bundle เพื่อผูกว่ารอบใหม่มาจากการทบทวนครั้งไหน

**ถ้ามีเกิน 5 ตัว** ให้ทำ 5 ตัวที่ธงหนักสุดก่อน (broken > escalate > ครบ 8 สัปดาห์) แล้ว **หยุดถาม user** ว่าจะทำที่เหลือต่อไหม — กันค่าใช้จ่ายพุ่งโดยไม่ตั้งใจ ตัวละ ~200k token

**4. เก็บกวาดคลังข่าว**
```
node scripts/archive-items.mjs --apply
```
ย้ายข่าวเก่าเกิน 75 วันที่ไม่ถูกอ้างในทฤษฎีปัจจุบันเข้ากรุ (ไม่ลบ)

**4.5 ทบทวน insight ที่ครบกำหนด** (ถ้าโควตาค้นเว็บยังเหลือ)
```
node scripts/list-hints.mjs --due=14
```
ถ้ามีคิว ทำตาม `/review-hints --max=5` (ไม่เกิน 5 เรื่องต่อสัปดาห์ — แต่ละเรื่องค้นเว็บได้ถึง 6 ครั้ง) · ถ้าโควตาใกล้หมดจากรอบหุ้นแล้ว ข้ามได้ แล้วบอก user ในสรุปว่ามี insight ค้างตรวจกี่เรื่อง

**5. สรุปให้ user ครั้งเดียวตอนจบ** — อ่านจาก DB ไม่ต้องจำเอง
```
node scripts/review-summary.mjs
```
เอาผลลัพธ์นั้นมาเรียบเรียงเป็นรายงานสั้นๆ โดย:
- **ขึ้นต้นด้วยตัวที่ต้องทำอะไร** (plan-live / plan-broken / escalate) ก่อนเสมอ
- ตามด้วยตัวที่น้ำหนักเปลี่ยน
- ตัวที่ยืนยันเดิมรวบเป็นบรรทัดเดียว (`ยืนยันเดิม 21 ตัว: AAPL, MSFT, ...`)
- ปิดท้ายด้วยตัวที่ข้ามเพราะ ingest ไม่ผ่าน (ถ้ามี) และคำเตือนว่าเป็นการศึกษา ไม่ใช่คำแนะนำการลงทุน

**"ไม่มีอะไรเปลี่ยน" คือผลลัพธ์ปกติของสัปดาห์ส่วนใหญ่** — สัปดาห์ที่ทุกตัวยืนยันเดิมคือระบบทำงานถูก ไม่ใช่ทำงานน้อย
