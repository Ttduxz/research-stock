ทบทวนสถานะของ insight ที่ครบกำหนด: $ARGUMENTS

**ทำไมต้องมีรอบนี้:** hint ถูกเอาไปปรับการวิเคราะห์หุ้นตัวอื่น (ขั้น 2.6 ของ `/research-stock`) ถ้าเรื่องไหนจบไปแล้วหรือถูกหักล้างแล้วแต่ยังถูกใช้อยู่ ผลวิเคราะห์หุ้นจะผิดโดยไม่มีใครรู้ — รอบนี้ตัดสินทีละเรื่องด้วยหลักฐาน แล้ว hint ที่ไม่ active จะหลุดจากขั้น 2.6 เอง (`list-hints.mjs --active`)

**กติกา:** agent `hint-reviewer` = opus (กำหนดใน spec แล้ว ห้าม override) · orchestrator **ห้ามอ่านไฟล์ JSON เอง** ส่งแค่ path · โพสต์บรรทัดเดียวต่อ hint · **"ยังมีผลอยู่" คือผลปกติของส่วนใหญ่**

## ขั้นตอน

**1. ดูคิว** (ไม่ใช้ agent)
```
node scripts/list-hints.mjs --due=<N ค่าเริ่มต้น 14>
```
ได้ hint ที่ยังมีผลและไม่ได้ตรวจเกิน N วัน เรียงตัวที่ตรวจนานสุดก่อน — ถ้า `--max` ถูกส่งมาทำแค่เท่านั้น (ค่าเริ่มต้น 8 เพราะแต่ละเรื่องค้นเว็บได้ถึง 6 ครั้ง และโควตาทั้ง session มี ~200) คิวว่าง = บอก user แล้วจบ

**2. วนทำทีละ hint**
```
DIR=pipeline/output/hint-review-<วันนี้>
node scripts/get-hint.mjs <slug> > $DIR/<slug>.hint.json
```
- spawn `hint-reviewer` ส่ง path `$DIR/<slug>.hint.json` + วันที่วันนี้ สั่งเขียนผลลง `$DIR/<slug>.review.json`
- `node scripts/ingest-hint-review.mjs $DIR/<slug>.review.json`
- ถ้าสคริปต์ปฏิเสธ (ไม่มีหลักฐานที่มี url / status ผิด) ส่งกลับให้ agent แก้ **หนึ่งครั้ง** ไม่ผ่านให้ข้ามแล้วบันทึกไว้รายงานตอนจบ — ไม่มี `--force`
- โพสต์บรรทัดเดียว: `<slug> — <สถานะใหม่>`

**3. hint ที่เพิ่งถูกปิด** (played-out / invalidated) — ต่อเรื่อง รัน
```
node scripts/hint-exposure.mjs <slug>
```
ได้หุ้นที่รายงานล่าสุดเคยอ้างถึงเรื่องนี้ → **ไม่ต้องรัน pipeline ใหม่อัตโนมัติ** แค่รายงานให้ user ว่าตัวไหนควรทบทวน (`/review-stock <TICKER>`) เพราะแผนของหุ้นพวกนั้นเคย factor เรื่องที่ไม่เป็นจริงแล้ว

**4. สรุปให้ user ครั้งเดียวตอนจบ**
- ขึ้นต้นด้วยเรื่องที่ถูกหักล้าง/จบแล้ว พร้อมเหตุผลหนึ่งบรรทัดและหุ้นที่ได้รับผลกระทบจากขั้น 3
- เรื่องที่ยังมีผลรวบเป็นบรรทัดเดียว
- ตัวที่ข้ามเพราะ ingest ไม่ผ่าน (ถ้ามี) · ปิดท้ายว่าเป็นการศึกษา ไม่ใช่คำแนะนำการลงทุน
